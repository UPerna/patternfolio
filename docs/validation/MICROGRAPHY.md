# Digital micrography

The `text/digital-micrography@1` provider implements the signed boundary optimization and doubled-angle field from Maharik et al., R08 sections 4.1–4.2. It samples three sites per side in a convex quadrilateral. Visibility is complete in this domain. Pair weights use angular similarity and the font-relative distance kernel. Opposite ray cones estimate attraction, with trimmed distances and norm scaling. The provider minimizes the source objective over all 4,096 Boolean labels with optional user locks. It records the chosen mask, weights, examined count and both all-label baselines. Exact finite search replaces the paper's stochastic active-set solver.

An alternating triangulation supports the least-squares doubled-angle field. Bounded Gauss-Seidel relaxation uses unit-weight soft tangent constraints. The implementation records the residual and requires a positive horizontal component across the interpolated representation. This restriction yields a nonsingular monotone field. Midpoint integration traces separated baselines with an explicit curvature cap. Lines are oriented left to right and ordered top to bottom in this bounded profile. It does not need the source's general cyclic line-ordering procedure. Whole words are fitted in order and the build fails if the text cannot fit at its declared size.

The portable font path uses a pinned licensed Latin Modern Math 1.959 subset and verified outline data. Its bounded shaping supports ASCII, basic Greek and declared Latin acute graphemes. It preserves decomposed input through a canonical outline alias and uses genuine fi/fl glyphs while retaining both source graphemes. Unsupported scripts and combining sequences fail explicitly. Shaping is deterministic and independent of installed fonts. It does not attempt general contextual OpenType shaping.

Both backends paint the same locally rotated glyph outlines. The PDF text layer uses ordered Type 3 glyph strings with ActualText and ToUnicode. An invisible logical line is anchored at the beginning of the visible line so text extractors can recover the text as a single string. SVG stores the actual Unicode text in ordered text elements and preserves spaces. The physical vectors remain visible in both. Views that would hide any glyph fail rather than offering misleading extraction. The acceptance checks independently audit the boundary objective, field residual, containment, curvature, counters, exact graphemes and extracted PDF/SVG text.
