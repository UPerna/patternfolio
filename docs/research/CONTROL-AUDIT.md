# Pattern controls and what they change

This audit applies the categories in Gieseke et al., [*A Survey of Control Mechanisms for Creative Pattern Generation*](https://onlinelibrary.wiley.com/doi/full/10.1111/cgf.142658), *Computer Graphics Forum* 40(2), 585–609 (2021), §§3–5, 7–8, consulted 2026-11-07. It maps the controls Florilegium actually exposes. The survey's other interaction methods remain research options.

The editor derives parameter widgets from the registered definition and input editors from fields in the selected recipe. The Lua implementation validates the same data as the CLI. See [studio workflows](../browser-editor.md), [recipe contracts](../architecture/RECIPES.md) and [document views](../architecture/DOCUMENTS.md).

| Mechanism | Available control and reach | When it applies | Contract and observed evidence |
| --- | --- | --- | --- |
| Exemplar | Replace or edit the DecoBrush library. It affects the selected guide and attached feature. The Escher recipe can carry a verified precomputed witness. | Before a structural generation. An existing instance can be replayed without the solver. | Design inputs, instance provenance, named input hashes. Editor exemplar import and malformed data checks; native Escher cache replay. |
| System parameters | Choose a seed and declared family parameters, with ranges from that definition. Scope can be the whole instance or the family feature named in the parameter. | Before generation. An unapplied structural draft retains the previous preview and disables its export. | Design specification and build record. Editor structural refresh, invalid intent, and botanical seed synchronization checks. |
| Visual parameters | Choose source paint, monochrome or the shared fill/stroke tint palette. These affect a scene's paint. Maze wall and solution views are available in that family. | After generation for supported view/style edits. | Drawable scene and native style/view revision. Exact instance replay, RGB/DeviceGray and export byte checks. |
| Handling | Move a visible guide point or edit exact coordinates. For a Celtic scaffold, edit declared vertices, edges and crossing pins. | Draft edits before regeneration, limited to input fields the recipe exposes. | Design inputs, graph/strand instance and independent topology validation. Editor canvas and knot workflows. |
| Filling and masking | Set a physical page and crop, or add protected rectangles. Reservations can be regional; their effect depends on the family planner. | Before generation when construction inputs change; after generation for admitted view clipping. | Validated document and view. Page-control checks, immutable tile identities, protected pixels. Micrography omits unsupported masks. |
| Guiding | Use declared stroke, maze, botanical or exemplar guide data. A maze uses a supported analytic tone field and optional guide stations. | Before generation. The guide constrains only the instance profile that declares it. | Family input validation, field or graph instance. Editor maze/brush checks and native source-specific fixtures. |
| Placement | Place an inline ornament or page panel in a declared slot in either TeX adapter or a collection. Browser crop, fit and pan change the view or preview. | After construction for placement and viewing; a different physical design context can require new generation. | Document view and renderer plan. Native LuaLaTeX/XeLaTeX Form placement and composition checks. |

Custom fonts, arbitrary bitmap imports for the maze, free editing of generated crossings, a browser-launched external optimizer and arbitrary drag-and-drop tile topology are outside these profiles. The preview alone does not certify a valid result. The editor exports a new result only after the registered validator passes and retains the prior valid result when a request fails.
