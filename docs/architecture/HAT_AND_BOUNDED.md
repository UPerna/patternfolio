# Hat hierarchy and bounded construction

`tiling/hat@1` implements the H, T, P and F metatile hierarchy from Smith, Myers, Kaplan and Goodman-Strauss. The HatViz placement and grouping data come from the pinned BSD-3-Clause reference. The Lua implementation builds the guide polygons and exact rigid child placements. It retains rational guide intersections and converts the normalized leaf coordinates to a single integer triangular chart by exact divisibility. [Published paper](https://escholarship.org/uc/item/3317z9z9) [Pinned reference](https://github.com/isohedral/hatviz/tree/4bb9d01999e4e84accc2a78d0fa279ef20b47263) [License](../research/licenses/HATVIZ-BSD-3-Clause.txt)

Each leaf uses eight elementary kites. The root proof checks the shared hex-center lattice coset, distinct kite occupancy, and opposite orientations of shared sides. Cancelling internal kite edges recovers each Hat outline. The connected root boundary has the same exact area as its leaf union. Source metatile guides determine placement and remain separate from the certified union. The hierarchy records parent and child addresses, and a crop keeps the root's leaf identities, global seam owners and chirality. The H root has both reflected and unreflected leaves. Hat geometry, straight Tile(1,1) and the curved Spectre have separate definitions and checks.

The first profile supports four roots at depths 1–3. It compares normalized coordinates, addresses, labels and orientation against twelve author-reference hashes. The larger rendered root has 169 Hats and the diagnostic draws the actual kite subdivisions. The source's infinite aperiodicity proof and the finite occupancy and area checks have different scopes.

`tiling/marked-square-completion@1` exercises the bounded constraint route independently. The problem admits a finite rectangular grid of up to 6×6 slots with explicit holes. Each occupied slot receives one blank, straight or elbow tile. Allowed orientations are explicit binary edge marks. Interior neighbors must agree, and fixed outer and hole boundaries default to zero unless the recipe supplies a mark.

The versioned solver visits slots in row-major order with a fixed tile order. A complete assignment is checked against the full problem before it is lowered into a graph. A saved assignment can replay with a zero search budget. Exhaustive failure yields `unsatisfiable`, a search-node limit yields `unknown`, and a host deadline yields `timeout`. Native code uses the available Lua CPU-time clock by default. A host can inject a monotonic seconds clock, which also makes the timeout regression reproducible. The build records keep the solver status, seed, declared limits, and exact problem and assignment digests. The deadline value and outcome are recorded without absolute time measurements.

The finite fixture verifies a path through a region with a hole. The impossible fixture has a single marked boundary edge. Every allowed tile has an even mark count and interior marks contribute in pairs, so the boundary is independently impossible. The local solution certifies its fixed finite problem.
