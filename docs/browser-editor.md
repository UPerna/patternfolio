# Local pattern studio

Build the browser files with `python3 tools/webpackage.py`, serve `build/web` with a local static HTTP server, and open its address. The editor loads its own verified assets; it has no runtime CDN, model API, or geometry service. The separate `runtime.html` page remains the internal runtime-verification harness. See the [quickstart](QUICKSTART.md) for a local server command.

Choose a starting recipe from the actual family registry. **Generate structure** runs its Lua generator and validators in a cancellable worker. **Apply settings** validates the native recipe and reuses an existing validated instance for style/crop changes. A structural change leaves the previous preview visible, disables its export buttons, and asks for explicit generation. Mathematical assumptions and the build record appear with the result. Finite-patch validation does not establish an infinite tiling theorem.

Page size, crop coordinates, guide/scaffold points and protected rectangles use centimetres in the recipe's existing frame. Page edits retain the native document planner and its physical requirements. Crop changes preserve anchored tile identities. Protect the page centre to create a border, or draw/enter individual rectangles. Unsupported masks are omitted for the Micrography profile. A mask clips a view; it does not repair topology or reroute every family.

Use Fit, +/− and the arrow keys with the canvas focused to navigate; 0 fits again. Guide/scaffold editing appears only when the chosen recipe supplies those inputs. Drag a visible point or edit exact coordinates in its JSON field. The Celtic scaffold exposes vertices, edges, authored open sectors and crossing pins. Inconsistent crossing alternation is rejected. DecoBrush accepts a JSON library array (or a recipe containing `design.inputs.library`); library primitives and guide stations remain editable. A native preflight validates the imported library before it replaces the draft.

Micrography exposes actual text and layout parameters with its pinned font identity. Its supported Latin/combining/Greek glyph profile and native text constraints apply; custom font loading and unsupported scripts are not offered. Maze guidance uses the family's analytic ramp/radial/ribbon/constant tone fields and authored guide points, rather than arbitrary bitmap input. Switch between walls and solution to view the native validated route without regenerating the maze. Precomputed solver inputs remain explicit recipe data; the browser does not launch native-process optimizers.

Original paint, monochrome and fill/stroke palettes change the native scene and both vector exports. Monochrome produces DeviceGray PDF paint; palettes are RGB tint treatments, not spot-colour separations. Opacity, clips, geometry and white gaps are preserved. The optional 3D network export appears only for a curve-network result; its PDF/SVG view is a visualization. There is no STL or manufacturing export.

Undo/redo retains validated snapshots. IndexedDB stores the current recipe, result, history and unapplied drafts after changes. Save Workspace exports a portable backup containing the current recipe, drafts and exact result assets; portable exports omit the potentially large local undo history. Opening a workspace checks asset hashes and replays the native instance to verify saved vectors before accepting them. An older core revision requires importing its recipe and regenerating, while the old workspace remains available as its original backup. Malformed imports and failed worker operations preserve previous work. A newer edit supersedes an older worker or import result.

Export Recipe saves the applied canonical recipe; unapplied form changes are retained in a workspace backup. SVG/PDF buttons export only a current accepted result. An active result keeps working with the network offline after its local runtime assets have loaded. Loading a fresh page still requires access to the static files; there is no installed service-worker/offline-site claim. Browser storage is origin-specific and can be cleared by the browser. Export a portable backup before moving the source folder, changing ports, or changing core revisions.

`tools/editorcheck.cjs` drives real browser tasks and compares downloaded files with the actual worker bytes. `tools/editor_vectors.py` independently inspects XML/PDF physical bounds, vector resources, DeviceGray and searchable text. Browser screenshots and enlarged vector renders require separate visual review. Development results do not replace native TeX or exact-revision CI gates.

Native packing and solver outcomes appear beside the preview. A validated build can contain a partial or empty mosaic packing; those labels remain explicit, with placed/rejected counts and native coverage. Validation does not imply that every requested site was packed or that an optimizer converged. Paint changes retain the native outcome.

Editor intent containers keep their native JSON types: parameter/input/style patches are objects; crop/page-size/rectangle lists are arrays. False-valued or wrong-container edits produce errors and keep the draft. Applied structural edits retain a clearly labeled previous preview across refresh until Generate is selected. Saved result identity follows the native canonical recipe digest, including when JSON object keys are reordered.
